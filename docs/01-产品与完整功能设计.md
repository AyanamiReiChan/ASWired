# 产品与完整功能设计

> 早期业务草案说明：本文仍保留旧版业务模型或原型交互供参考。自行提出的车主/多租户、AA账本、人工审批及付款流程不是本轮新增要求；角色、套餐和续费等实际行为以[第15份当前矩阵](15-完整功能与PRO对齐矩阵.md)及固定版本核对为准，不据旧稿另设流程。

> 当前决策（2026-09-15）：除PRO商业授权外，采用妙妙屋X的公开设计和固定版本行为，ASWired全部功能不设置付费墙。此前自拟的Agent多进程/mTLS、独立协调器、Vision拷贝替代、离线双策略及JWT刷新方案已撤回；当前节点、运行时、运维与登录规则以[13](13-子Agent详细设计.md)、[16](16-增强运行时与PRO执行设计.md)、[17](17-Agent运维测速与联邦设计.md)、[18](18-自有探针与登录回接设计.md)的0.3修订及[完整矩阵](15-完整功能与PRO对齐矩阵.md)为准。品牌、固定深色、三私有仓、JWT、自有探针和外部仅Komari1.2.5-fix2为用户既定要求。以下业务模型不是上游私有协议声明，尚未实现。


## 1. 产品定位

ASWired 是面向自建线路管理员、共享车主与成员的 Xray 资源管理系统。把“服务器是否正常”“成员拥有什么权益”“配置是否实际生效”“费用是否确认”放在一条可追溯业务链中。服务器是基础资源，套餐定义权益，车队分配席位，订阅负责分发每人的独立凭据。

目标不是将不同面板嵌入 iframe。所有页面和业务 API 属于 ASWired；受管 Xray 可以采用原生 Agent，也可以由 3X-UI 适配器渐进接管。前端继续使用用户确认的 SvelteKit/Svelte 5 与 AcoFork 视觉体系。

## 2. 角色与范围

平台管理员负责组织、密钥和全局配置；运维负责线路、证书和发布；财务负责费用及人工核销；车主管理自己车队的席位、邀请与费用；成员只见自身套餐、流量、订阅和账单；审计员仅能读被授权的脱敏记录。默认创建一个个人工作区，但模型预留 tenant_id，避免以后重做权限边界。

公开探针可匿名或受访问密钥保护，仅读取自有采集或 Komari 来源的独立白名单投影。内置及独立探针均有 ASWired 密码/Passkey 登录入口与回接，登录后仍按角色返回授权页面。Xray 管理 Agent、Komari 连接、外部主控与 API Token 是独立机器身份，不复用成员登录角色。TG Bot、Mini App 与 MCP 不能越过同一套资源授权。

## 3. 新用户与资源开通路径

安装控制端 → 创建工作区与管理员 → 添加服务器库存 → 选择原生 Agent 或 3X-UI 只读导入 → 核对节点身份和能力 → 创建入站并预检 → 生成自建节点 → 绑定模板及套餐 → 创建车队 → 邀请成员 → 预留席位 → 核销或确认免费开通 → 授予权益 → 下发各节点独立客户端 → 收到逐节点回执 → 发布订阅快照 → 成员导入客户端。

任一步失败都显示具体阶段。例如款项已确认但东京节点离线，订单显示已收款，交付显示部分生效；不能把已付订单改为失败重收款，也不能显示所有线路可用。

## 4. 完整业务域

### 4.1 身份、登录与外观

账户支持创建、停用、受控删除、资料修改、TOTP、恢复码、Passkey、JWT用户认证、API Token 权限和订阅短码轮换。Turnstile 是可选防滥用集成，并有可访问性回退；不能让机器人验证替代身份验证。管理员本机恢复通过离线单次令牌与审计完成，不提供公开 HTTP 后门。支持关闭注册、本地监听、品牌/菜单配置、中文/英文和移动适配。全站固定深色外观，不提供白天模式、个人主题覆盖或主题切换。

手机/官方客户端登录能力映射为 ASWired 自有设备授权流程：展示设备请求与有效期，由已登录用户确认，轮询只返回本设备受限 Token；不假装兼容上游私有客户端协议。

JWT登录、MM-Authorization请求头、过期重新登录及探针回接按上游公开设计核对；不再强制自拟EdDSA、Cookie-only或刷新令牌期限。具体字段与注销效果见[JWT与登录回接](18-自有探针与登录回接设计.md)。

### 4.2 服务器与内核运行

库存包含区域、服务商、IPv4/IPv6/域名、到期、成本、周期流量、入出站倍率和备注。Agent采用WebSocket/HTTP/Pull及Auto回退，节点Token与主控公钥建立加密通信；外置Xray为独立进程，内嵌Xray与Agent同进程，安装/重启按第13–17份0.3方案。内核版本、扩展协议与适用模式按锁定上游样例验证，不能把未知私有实现改成任意sidecar替代。

受管入站固定为 VLESS + TCP + REALITY，校验端口、REALITY 密钥/SNI、Short ID、Flow 和嗅探。其他协议与传输不再作为入站创建、启用和发布选项。旧记录保留供停用、删除或由用户明确转换；转换后须补齐 REALITY 参数。当前实施范围以 [范围说明](CURRENT-SCOPE.md) 为准。

提供 Xray/Nginx 启停、版本升级、配置历史、差异、漂移检测、备份与回滚。一次配置只有一个写入者。Reality 本机网站复用通过显式站点依赖实现，避免端口和证书相互覆盖。DDNS 更新后触发受影响节点地址与订阅快照重编译。

### 4.3 出站、路由与转发

当前出站代理限定 VLESS TCP REALITY，保留出站排序、直连/阻断及端口转发。早期代理链、负载均衡与系统隧道设计须按当前实施范围核对。路由支持域名/IP/端口/协议匹配、嗅探目的地、规则排序、预设与命中诊断；DNS 单独编译，避免规则循环和 DNS 泄漏。专家改动以整个配置版本审核，不直接拼接字符串。

同时覆盖整节点链式出口、套餐路由子节点、成员私有子节点、客户端中转组、Xray Tunnel、端口转发、复用入站的目标转发、Agent 转发组与链。转发模型有监听端点、目标引用、上级链、授权主体、流量归属、连接限制、健康检查和计量能力。链图必须无环，端口按运行节点唯一。成员自助有功能开关、可用节点范围、持有数量及每日操作上限；不能由成员提交任意 shell 或系统路径。

### 4.4 节点与测速

节点仅支持 VLESS TCP REALITY，可从自建入站、标准 URI、文件、外部订阅、成员自有资源导入；解析为统一结构后保留原始来源 ID 与兼容参数。支持 CRUD、批量启停、标签、排序、前缀/后缀、地区显示、临时订阅、用户 URI 汇总、去重、地址修正和外部重同步。删除上游节点先标记撤回，保留引用审计。

提供 TCP 延迟、域名解析、有限量下载测速、家用测速端与回程诊断。测速必须有显式并发、字节预算、超时和授权目标，显示测量地点及时间。云端结果和家宽结果分开，不能把两者平均为一个无上下文数字。

### 4.5 订阅源、转换与分发

外部订阅只接入符合 VLESS TCP REALITY 的节点，支持定时、按需、缓存刷新、保留/排除匹配、稳定映射、变更通知、来源所有权、来源流量元信息、家庭抓取端和代理集合。失败保留最近成功快照但显示过期时间；空订阅与抓取失败不同。远端流量额度仅为供应商整体参考，不作为某位成员实际消耗。

目标输出覆盖 Clash/Meta、Surge、Loon、Quantumult X、Shadowrocket、sing-box、Stash、Surfboard、V2Ray、Egern。编译器先形成统一节点/组/规则 AST，再按客户端与版本导出；不支持字段须返回可读诊断，禁止静默删掉安全参数。支持 UA 自动选择、独立分发域名、手动格式、订阅文件管理、文件导入导出、标准流量头、节点排序、临时短码、访问白名单、设备策略和立即撤销。格式支持表必须标注客户端版本，CI 使用固定 golden 样例并在实际客户端验证。

### 4.6 模板、脚本与规则

完整纳入模板 CRUD、版本兼容、共享、内置/远程/自定义/导入/账户私有/动态生成六类来源、可视化与代码编辑、动态匹配、区域组、空组处理、代理组选路、订阅自动再生成、DNS/规则/规则集覆写、远程代理组和规则集托管。合并优先级固定为内置基线 < 套餐模板 < 用户覆写 < 强制安全规则；冲突提供可读差异。

JavaScript 覆写作为高级能力保留，但只在隔离 worker 中运行：无文件系统、无网络、无凭据，输入为脱敏节点 AST，输出须通过 schema，设置 CPU/内存/输出大小限制、终止能力与版本签名。执行前预览差异，订阅请求路径仅消费编译缓存。前端演示不 eval 用户脚本。

### 4.7 套餐与拼车

支持套餐模板、独立多套餐实例、绑定/解绑/续期、续费工作台、总额度/单节点额度/覆写、节点范围、按客户端模板、计费倍率、到期/超额动作、自助续费、邀请码/兑换码和所有套餐合并订阅。倍率使用固定点有理数，生成独立消耗条目，不能在已计量字节上重复乘。

套餐、拼车和成员转发按当前上游行为保留。历史官方拼车市场在新预发布已移除，不自行创建本地市场替代。早期车主角色、席位/AA/人工核销与账本扩展只留历史草案，不作为本轮新增流程。

### 4.8 限速与接入控制

支持用户及套餐速度上限、并发连接数、同时在线 IP、行为自动限速、超额降速和恢复。执行依赖 Agent 对各传输的能力报告；无法准确识别的设备/IP 必须显示未知或降级。多种暂停原因独立记录；额度刷新不能顺带清除安全封禁。反共享策略仅用于限制风险，不能保证已下载配置不可复制。

### 4.9 证书、站点与域名

统一 DNS 服务商凭据、ACME 申请/续期、证书导入导出、部署更新、Certimate Webhook、站点 CRUD、反向代理和静态站点。DNS API Key 使用区域级最小权限，证书私钥与证书链分开控制导出。验证请求按目标绑定，不能用证书管理充当任意内网 HTTP 探测器。网站与 Xray 共用端口须经过端口预检和可回滚发布。

### 4.10 监控、探针与流量

完整保留 ASWired 自有采集、内置及独立部署探针、状态HTTP/实时WS、1h/6h/24h历史、3D地球、品牌、隐蔽登录入口与原登录页屏蔽、密码/Passkey登录回接。公开 `/probe` 只展示获准服务器与字段。仅外部第三方探针支持 **Komari 1.2.5-fix2**；双来源按稳定身份分别绑定与存储，管理员明确选主展示源。详见[自有探针与登录回接](18-自有探针与登录回接设计.md)和[Komari接入](12-Komari探针接入设计.md)。

管理员与成员用量视图分离。Xray 内核状态、在线客户端、连接、配置回执由独立管理链路提供；套餐流量、充值、消费、调整和未知量来自计量账本，不能使用原生或 Komari 主机网卡流量代替成员计费。普通连通性测速、网络质量与回程诊断保持各自来源、测量地点及时间；本次探针范围变更不删除这些能力。当前前端仅展示合成数据，不表示已连接 Komari。

### 4.11 通知、Bot 与公告

Telegram、邮件、站内、Webhook 由事件模板系统驱动：阈值、到期、离线、恢复、日报、续费、发布失败和订阅变化。规则有接收范围、阈值、冷却、去重键、静默窗口、重试和失败队列。公告支持全站/套餐/成员定向、发布时间和阅读状态。TG Bot 注册绑定必须在登录态中确认 TG 用户，成员与管理员命令分级；Mini App initData 服务端验签与时效校验，不能信任前端 userId。

### 4.12 联邦与集成

跨主控分享节点和订阅元信息，有方向、范围、过期、撤销、来源白名单和加密通道。外来主控不能继承本地管理员权限，远端事件带发行方和资源命名空间，防止同名覆盖。共享令牌按受众绑定，不把自建成员凭据泄漏到未经授权的对端。

提供分级 API 和 MCP 工具：查询、预览、提交分开；沿用同一授权与审计。上游最新说明的 109 个 MCP 工具属于参考覆盖数量，公开资料不足以确认每个私有工具 schema；ASWired 以本设计资源 API 建立自己的工具清单，不虚构完全相同的接口兼容。原型仅注册三个用于页面查询/导航的演示工具。

### 4.13 数据维护、升级与迁移

生产支持 PostgreSQL；单机轻量版可后续提供 SQLite，必须统一 SQL 迁移和事务语义，拼车并发基线以 PostgreSQL 为准。备份包含业务库、对象、配置、证书与密钥版本清单；可定时保存到本地、S3、WebDAV、Google Drive。迁移妙妙屋以用户合法导出的文件为输入，先识别版本、映射 ID、预览冲突和导入范围；闭源备份结构不预先承诺兼容。3X-UI 迁移先只读，凭据映射核对后再接管。禁止对旧系统自动卸载。

安装升级支持稳定/预发布通道、签名校验、数据库迁移、备份、受控重启和回滚。日志中心脱敏并有保留期。原PRO功能全部在ASWired开放，不存在商业激活、付费开关、许可证续期或授权槽位；技术能力检测与用户/节点鉴权仍保留。不修改上游付费二进制以绕过其授权。

## 5. 非功能目标与完成定义

基线容量以 50 台受管服务器、1000 成员、10000 客户端绑定进行压测；目标是常规列表 p95 < 500 ms、订阅命中缓存 p95 < 200 ms、普通遥测每节点批量15–30秒，探针观测/公开WS默认5秒目标且独立限流、发布可见进度 < 2 秒。以上为待压测指标，不是原型成绩。RPO/RTO、配额上界和各客户端兼容性均须通过记录可复现的验收才对外承诺。

所有 146 项上游公开功能均列入矩阵；UI 已展示的流程与后端待实现能力独立标识。先建立一致的权限/计量/交付核心，再扩展联邦、客户端和高级脚本，不以任意“成功”提示代替功能实现。
