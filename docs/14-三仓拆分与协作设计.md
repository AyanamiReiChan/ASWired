# 三仓拆分与协作设计

状态：**设计 v0.3，待确认，仓库尚未拆分**。日期：2026-09-15。

本轮按用户最新决定：除 PRO 授权外，采用妙妙屋 X 的公开产品与运行设计；ASWired 不设置许可证服务器、PRO 付费墙或按付费状态隐藏功能。项目仍使用 ASWired 品牌、固定深色，保留自有探针、JWT 登录回接；外部第三方探针只接 Komari 1.2.5-fix2。

本文件仅是设计，不代表已经创建仓库、迁移代码或完成实现。现有 `AyanamiReiChan/ASWired` 保持私有，新增仓库也默认私有；公开需要用户另行明确决定。

## 1. 三个独立仓库

| 仓库 | 职责 | 交付物 |
| --- | --- | --- |
| `AyanamiReiChan/ASWired` | 网站、管理与成员页面、内置/独立探针、JWT登录回接、固定深色与CSS | 网站构建、独立探针构建、可选Worker展示与回接适配 |
| `AyanamiReiChan/ASWired-Server` | 主控API、账户/套餐/订阅/账务、Agent连接、联邦转发、历史与公开投影、Komari适配 | 主控程序、数据库迁移、接口契约、发布与部署说明 |
| `AyanamiReiChan/ASWired-Agent` | 节点Agent、同进程embedded核心、external适配、自有采集、运维网络、家用测速端 | 原生Agent、host网络Docker镜像、安装器、独立测速端、fakecontrol |

保留网站仓名 `ASWired`，保持既有克隆地址与链接。两个新仓命名明确，不把现有网站改名来追求对称。

三个仓库各有自己的 Git 历史、构建与 release，不使用嵌套 Git 仓库或强制 submodule，也不新增第四个共享源码仓。多个部署产物不等于多个源码仓：独立探针/Worker仍归网站仓，家用测速端仍归Agent仓。

主控、网站和数据库可以同机部署；节点运行 Agent。主控仓内的异步任务、订阅、历史和联邦模块可以按实际部署运行，不要求先拆成独立微服务。

## 2. 采用的运行结构

### 2.1 节点运行模式

| 模式 | 进程与控制 | 安装与升级 |
| --- | --- | --- |
| `embedded` | xray-core及对应管控模块嵌入Agent同一进程，随Agent启动/停止 | 更新Agent同时更新内嵌核心；提供完整原PRO能力，无授权锁 |
| `external` | 独立Xray进程，Agent通过gRPC管理 | 原生安装默认模式，核心可以单独升级 |
| Docker | Agent镜像内置embedded核心与Nginx，使用host网络 | 按镜像拉取/重建方式升级，保留配置与证书挂载 |

以上采用[公开Agent部署设计](https://miaomiaowux.com/docs/install-agent/)；具体核心版本、热变更和协议能力统一见 [Agent总体设计v0.3](13-子Agent详细设计.md) 与 [运行时设计v0.3](16-增强运行时与PRO执行设计.md)。

采集、连接、策略与本机操作作为 Agent 内部模块运行。原方案中的独立 helper、observer、coordinator、增强runtime子进程不再作为本方案结构；不要求用户安装这些服务。

### 2.2 节点身份与连接

节点使用每服务器独立凭据、主控地址和主控公钥建立上游所述加密信道，支持WebSocket、HTTP、Pull及自动回退。Server Token用于Agent连接主控，Agent Token用于主控调用Agent；安装字段映射和轮换窗口按固定版本核对。凭据绑定唯一服务器，不把同一份配置复制给多台节点。

这替代旧稿默认的自建mTLS PKI、节点证书引导、独立命令签名会话和helper启动挑战。未知的secure channel握手、消息格式与密钥派生不能以旧稿自定义协议顶替，须按13列出的证据与验证任务完成。

普通启动、掉线重连、在线升级、重装和卸载按公开行为实现；不增加availability/accounting两种产品模式、双槽升级或“每次节点启动先等主控许可”等用户门槛。

## 3. 职责与数据权威

### 3.1 网站仓

- 维护SvelteKit/Svelte 5/TypeScript界面与全部普通/原PRO入口，按用户角色检查操作权限，不检查付费授权。
- 网站只访问主控API；服务安装、入站、路由、证书、限速、测速与共享均展示实际任务进度和结果。
- 内置与独立探针共用展示组件，提供实时/历史、品牌/CSS和登录入口，全部保持固定深色。
- 独立探针静态资源、只读API和WS代理按公开部署方式提供；登录回接机制以18固定版本核对结果为准。这是自有展示端，不是新的第三方探针供应商。
- 密码/Passkey登录接入ASWired自身JWT与会话体系。探针读取凭据、节点token和Komari凭据均不能作为用户登录态。
- 保留演示模式标识；前端原型中的模拟成功不能作为节点已生效的证据。

### 3.2 主控仓

- 管理用户、角色、套餐、多套餐权益、订阅、拼车、流量计量、节点库存与公开业务行为；不新增早稿AA或财务审批体系。
- 生成安装命令和Docker变量，管理节点token、公钥配置、加密连接、版本、服务操作和配置历史。
- 实现原PRO涉及的用户/套餐限速、连接/IP规则、自动降速等配置与状态；实际执行由Agent/core按16完成。
- 保存Agent原生主机观测及历史，提供公开服务器/字段白名单投影；独立保留Komari 1.2.5-fix2外部来源。
- 管理签名JWT签发、校验、过期重新登录及自有探针回接；存储和注销/停用效果按固定版本核对，细节见[自有探针与登录回接](18-自有探针与登录回接设计.md)。
- 管理DNS/ACME/Certimate、WARP相关配置、转发编排、测速来源、TG/MCP、订阅覆写与备份。
- 联邦owner管理分享授权与转发，不解密consumer操作正文；不是consumer业务配置的明文编译中间人。
- 持有跨仓契约权威和兼容记录，不接上游PRO许可证服务。

### 3.3 Agent仓

- 一个Agent程序承担连接、加密消息、本机服务管理、配置与用户操作、原生观测及策略执行。
- embedded核心与Agent同进程；external核心独立运行并经gRPC控制，双方能力和故障表现分别验证。
- 实现Xray/Nginx安装、启停、更新、配置恢复、证书部署、转发、WireGuard/WARP与地址观测。
- 原生采集在Agent内部运行，区分主机和容器可见范围，观测错误不伪造成零值；主机网卡指标不代替成员计费。
- 家用测速/订阅抓取端为本仓独立程序 `cmd/aswired-speedtest`，支持Linux/Windows/macOS，不创建第四仓。
- 本仓保留fakecontrol与测试样例，开发者不必同时检出网站和主控。

同一实际Xray配置仍只由一个管理方控制。3X-UI与Agent不能同时覆盖同一实例；联邦consumer也不成为第二个Agent直接控制者。

## 4. 协议边界

```text
网站/内置与独立探针 ── 用户API / JWT / 公开读 ──> 主控
节点Agent <── token + 主控公钥 + 加密信道 ──────> 主控
  ├─ embedded：Agent进程内核心与管控模块
  └─ external：gRPC ──> 独立Xray
consumer ── ECDH端到端密文 ──> owner转发 ──> Agent
```

| 边界 | 契约内容 | 不能混用 |
| --- | --- | --- |
| 网站 ↔ 主控 | 用户API、角色权限、任务状态、JWT与登录回接 | 不能把Agent或Komari凭据下发为浏览器会话 |
| Agent ↔ 主控 | 节点token绑定、加密通道、WS/HTTP/Pull消息、状态与操作 | 不能将旧稿mTLS/签名信封当成上游已验证协议 |
| embedded内部 / external gRPC | 固定核心版本的配置、用户、统计、连接控制 | 不能由同名字段推定两个模式行为相同 |
| consumer ↔ Agent，经owner | ECDH密文、授权范围、转发限制与回执 | owner不得取得consumer操作正文；consumer不直接连接Agent |
| 自有探针 ↔ 主控 | 原生历史/公开投影与JWT回接 | 外部Komari登录和只读密钥不产生ASWired用户身份 |

[公开联邦设计](https://miaomiaowux.com/docs/share-server/)确认owner是唯一Agent直接控制者，consumer操作经owner转发并使用ECDH端到端加密。公钥身份绑定、密文与分享授权关联、路径白名单和全配置授权如何在Agent验证，属于尚需证据/实机核验的协议细节，不在本稿编造。

## 5. 契约权威与独立开发

确认后在主控仓维护下列目录，内容按已核验实现逐步冻结：

```text
ASWired-Server/
  contracts/
    user-api/v1/openapi.yaml
    agent/v1/schemas/
    agent/v1/golden/
    federation/v1/
    probe/v1/
    compatibility.yaml
```

JSON Schema与golden fixtures记录公开/已验证的字段、样例、错误和行为。私有握手尚不明确时标为待验证，不用一个自建schema证明兼容。公开能力、协议已核验、代码已实现、实机通过是不同状态。

契约制品独立版本化发布，包含来源、commit、版本、摘要和样例。Agent和网站各自锁定所需版本，可在仓内保留契约快照；构建不静默跟随主控默认分支，也不引入第四个共享源码仓。

消费仓的契约修改回到主控仓审核；生成类型或适配代码可以留在消费仓。样例只使用测试token与测试密钥，不保存真实节点秘密、用户JWT或上游许可证材料。

Agent仓自带 `cmd/fakecontrol`，模拟服务器token绑定、连接/断线、操作请求、结果、原生观测与异常响应。测试使用ASWired已明确契约；未核实的上游加密消息不能伪装成通过了兼容测试。

| 单仓场景 | 应验证结果 |
| --- | --- |
| embedded与external | 前者与Agent同进程，后者经gRPC管理独立核心 |
| 注册与连接 | 错误token/公钥配置清楚报错，节点不会绑定到别的服务器 |
| 断线重连与回退 | 状态恢复、请求结果可核对，不重复创建资源 |
| 用户/配置变更 | 实际核心状态与回执一致，失败保留可恢复信息 |
| 主机观测 | 时间、来源、容器范围与缺值准确，不污染计费 |
| 安装更新与恢复 | 重启后的版本、配置和真实连接符合预期 |

fakecontrol是开发工具，不能作为真实主控投产。主控联调与实际核心、加密信道互通验收是后续必须补齐的证据。

## 6. 三仓CI与版本

- 网站：类型与构建、完整功能入口、角色权限、固定深色、内置/独立探针与JWT回接。
- 主控：API与样例、账户/套餐/订阅等业务、节点身份与连接、历史/公开范围、联邦密文转发和JWT隔离。
- Agent：双模式、采集、用户管控、WS/HTTP/Pull、安装/更新/卸载、各平台构建与运行。
- 集成：固定Server/Agent/core版本组合，真实代理连接、测速、证书、转发及两主控共享。

主控仓记录已验证兼容矩阵：网站版本、Server版本、Agent版本、核心版本、模式、平台、协议与结果。新Server对当前/上一受支持Agent、新Agent对当前/上一受支持Server分别验证；只保证明确声明并通过的组合。

CI优先使用固定版本制品与契约快照，不要求三个源码仓同步checkout。各仓独立release和版本号；网站改文案不必重发Agent。embedded更新必须同时记录内嵌核心版本，external更新单独记录核心版本。

运行变更用发布说明讲清影响和恢复方式；不增加许可证校验或PRO解锁步骤。不可验证的私有协议项保持未完成，不能因为取消收费就声称可使用或绕过上游授权。

## 7. 现有历史与文档迁移

现有ASWired Git历史与 `frontend/` 路径先保留。两个新仓从明确基线开始，迁移清单记录原路径、原commit、新权威位置和来源；不把三个副本当作三个可独立维护的权威版本。

| 现有内容 | 后续归属 |
| --- | --- |
| 前端、页面、演示、自有探针组件与Worker | 网站仓 |
| 产品、账户/套餐/订阅、数据模型、API、JWT/公开投影、联邦契约 | 主控仓 |
| Agent架构、安装、双模式、采集、网络与测速实现说明 | Agent仓；跨仓协议仍以主控契约为准 |
| 原创审计与功能矩阵 | 保留来源基线，按引用或版本化快照分发 |
| `frontend/static/docs/` | 网站继续提供带来源与版本的文档副本 |

旧文档记录当时事实，并标明v0.3后续权威设计。第三方全文研究快照不分发；必要许可证、来源与依赖说明保留。自有实现不接PRO许可服务，不意味着可以无授权复制闭源核心、复用商业凭据或修改上游许可验证。

## 8. 实施顺序

| 阶段 | 三仓协作内容 | 出口 |
| --- | --- | --- |
| 确认 | v0.3架构、三仓与无付费墙范围 | 仍为设计，不建仓、不部署 |
| P0 契约 | 私有仓初始化、公开证据与待验证项、接口样例、fakecontrol、CI | 每项功能有责任和验收；未知私有协议明确登记 |
| P1 运行时与身份 | 同进程embedded、external gRPC、token/主控公钥/加密信道、三种连接、原生采集、JWT基础 | 真实主控与节点、原生观测及账户基础连通 |
| P2 用户管控计量 | 全部原PRO执行、用户/套餐策略、连接/IP、计量和恢复 | 功能在真实数据通路执行，无许可证门槛 |
| P3 运维部署 | 官网安装方式、host Docker、更新/重装/卸载、Nginx/证书、探针部署、转发/WARP/WireGuard/DDNS | 真实部署与资源生命周期可验收 |
| P4 测速联邦 | 主控/家庭测速、源抓取、consumer加密共享与全配置授权 | 真代理路径与owner不可读正文、单一直接控制者通过 |
| P5 全业务网站 | 全业务与原PRO页面、固定深色、JWT登录回接、自有探针/Komari整合 | 入口连接真实实现，权限、来源与结果一致 |
| P6 完整发布验收 | 原146项和细化项、多平台/协议/跨版本、升级恢复 | 必做项逐项通过；未知不算完成；三仓仍私有 |

本方案的决定是：**三私有仓、妙妙屋公开运行设计、完整普通/原PRO能力、自有JWT探针与登录、无PRO授权或付费墙。** 实现及验证细节随13、16、17、18和总矩阵共同完成，不恢复旧稿的独立特权进程或自建默认PKI方案。
