# 安全、权限与可靠性

> 早期业务草案说明：本文仍保留旧版业务模型或原型交互供参考。自行提出的车主/多租户、AA账本、人工审批及付款流程不是本轮新增要求；角色、套餐和续费等实际行为以[第15份当前矩阵](15-完整功能与PRO对齐矩阵.md)及固定版本核对为准，不据旧稿另设流程。

> 当前决策（2026-09-15）：除PRO商业授权外，采用妙妙屋X的公开设计和固定版本行为，ASWired全部功能不设置付费墙。此前自拟的Agent多进程/mTLS、独立协调器、Vision拷贝替代、离线双策略及JWT刷新方案已撤回；当前节点、运行时、运维与登录规则以[13](13-子Agent详细设计.md)、[16](16-增强运行时与PRO执行设计.md)、[17](17-Agent运维测速与联邦设计.md)、[18](18-自有探针与登录回接设计.md)的0.3修订及[完整矩阵](15-完整功能与PRO对齐矩阵.md)为准。品牌、固定深色、三私有仓、JWT、自有探针和外部仅Komari1.2.5-fix2为用户既定要求。以下业务模型不是上游私有协议声明，尚未实现。


## 2. 身份、权限与安全边界

### 2.1 角色与资源范围

| 角色 | 允许 | 不能默认允许 |
| --- | --- | --- |
| 平台Owner | 组织、平台配置、角色授予、灾难恢复、密钥策略 | 日常操作不必使用Owner会话 |
| 运维Admin | 节点、模板、发布、证书、故障处理 | 修改金额账本、擅自确认付款 |
| 财务 | 账期、费用、付款核销、退款、AA分摊 | 读取代理密钥或任意部署配置 |
| 团长 | 自己拼车组、邀请、成员席位、费用建议、组健康 | 他人订阅明文、服务器root、直接修改节点API |
| 成员 | 自己席位、用量、账单、独立订阅、设备登记 | 其他成员IP/凭证/付款资料 |
| 只读审计 | 指定范围事件和脱敏账本 | 新增、删除、执行、读取密钥 |
| Agent主体 | 指定node的任务、自身指标和回执 | 查询全租户客户或其他node |

所有资源有 `tenant_id`；数据库外键和查询都限定租户，不能只在前端隐藏按钮。团长权限来自 `group_memberships` 对具体group的关系；服务器共享给某组须经过明确resource binding。高权限账号启用MFA，密钥/订阅重新显示可要求近期重新验证；普通列表默认仅返回fingerprint和尾部标识。

关键动作审计：actor、tenant、action、resource、request_id、operation_id、前后摘要hash、时间、结果、来源IP及授权理由。审计中不保留完整订阅URL、token、代理password或支付回调原始密钥。IP与设备元数据设置有限保留期，成员仅能查看自身信息。

### 2.2 控制面与Agent

- 每台Agent使用独立token及主控公钥，遵循上游加密通信、配对与轮换设计；不自建mTLS身份体系替代。
- 内嵌核心与Agent同进程；外置Xray独立，通过gRPC控制。进程权限、服务账户与本机接口暴露按固定上游安装/运行样例核对，不再强制helper/observer/coordinator进程拆分。
- 用户、订阅、Agent、探针读密钥各自鉴权；消息/安装制品来源验证继续保留。去除商业许可证及付费Guard不等于去除身份或完整性检查。
- 具体加密握手、防重放、密钥更新与失败处理列P0验证，未知字段不填入旧自拟协议。公开上游说明与当前目标见第13、16份0.3设计。

### 2.3 Komari 连接与公开只读投影

自有探针采集使用已验证 Agent 身份；外部第三方探针仅接入 Komari 1.2.5-fix2。连接地址和凭据由管理端配置，密钥只供后端读取；演示前端仅保存凭据引用，不保存真实 API Key。适配器仅调用经固定版本验证的只读方法，Komari 凭据不授予 ASWired 用户身份或 Xray 配置权限。

公开读取先按服务器白名单筛选，再按字段白名单构造新对象，不把原始上游响应透传给浏览器。公开字段可选显示名、地区、在线状态、CPU/内存/磁盘占用、网络速率与采样时间，分别以原生采集权限及 Komari 固定版本实测可用为准。禁止包含管理 URL、服务器地址、内部 UUID、凭据、成员身份、连接来源 IP、订阅链接、费用账单。更改或关闭公开范围后，旧缓存必须失效；上游断连显示过期或未知，不能公开原始错误响应。



### 2.4 JWT用户认证与探针回接

网站和自有探针用户登录采用JWT，API头为MM-Authorization，过期重新登录，精确算法/claims/存储/回接和注销按第18份0.3核对。撤回固定EdDSA、双令牌刷新、即时sid查询等自行决定。JWT签名和用户/资源权限仍必须验证；Komari和探针读密钥不能换取用户身份。

## 14. 备份、恢复与密钥灾难恢复

### 14.1 备份范围

- PostgreSQL基线备份与WAL，覆盖业务、金额/配额账本、Outbox、操作、映射和审计。
- 不可变模板、manifest、已发布配置、证书、凭据封装和备份manifest；对象存储版本化。
- KMS配置/离线恢复材料与密钥版本清单；恢复材料与加密数据分地保存，不能把唯一解密密钥放在同一份数据库。
- 各节点Agent/核心实际版本、配置、证书引用、已确认统计基线与恢复材料、节点身份配置；当前备份与恢复范围以19为准，不使用旧稿sidecar/epoch/ack/lease字段推定上游机制。

建议初始目标可设控制面RPO≤5分钟、RTO≤60分钟，前提是部署并验证WAL及恢复流程；这是验收目标，不是当前保证。凭证撤销事件和付款事实尽量有独立追加归档，避免恢复旧库复活旧权限或重复确认付款。

### 14.2 恢复流程

1. 选定备份和恢复点，校验签名/hash/可解密，计算会丢失的事件窗口；隔离环境恢复验证后再切生产。
2. 暂停会扩大恢复差异的业务写入；已有节点按固定上游版本恢复语义运行，不引入自定义有限lease。
3. 恢复数据库、对象和密钥引用，校验迁移版本、账本借贷、订单合计、quota不变量和Outbox/inbox。
4. 核对主控身份、节点token和控制归属，避免克隆主控并行写；具体轮换/重新配对行为按固定上游版本执行。
5. 向付款渠道核对恢复窗口内实际付款/退款，按原event/receipt ID补入；绝不能从旧数据库状态推断外部付款没有发生。
6. 核对各节点实际配置、累计计数与恢复窗口；未知用量显式记录，不把旧库低用量当作新免费额度；不要求自拟lease终态接口。
7. 合并最新撤销与权限记录，再重建订阅快照；完整复测后恢复销售/发布。

复制数据库到另一台服务器时必须处理node identity、panel GUID和密钥归属；克隆实例不得以旧节点身份同时在线。备份恢复造成计数器回退时，按固定上游版本核对恢复与统计基线，不自定义generation通信协议。

3X-UI整库restore会重启，且数据库不等于全部外部证书和加密材料。[官方备份说明](https://github.com/MHSanaei/3x-ui/blob/837addf66e945a80080273b5d2a315dea765d748/docs/content/docs/en/operations/backup-restore.mdx)。恢复演练至少覆盖空白机器、错误证书、丢失keyring、旧schema、对象缺失以及部分节点离线，不以“备份上传成功”代替恢复成功。



## 导入、模板、脚本与联邦防护

远端订阅/模板/规则拉取只允许授权 HTTPS 来源，解析每次 DNS 结果，拒绝 loopback、link-local、元数据地址与私有目标；对合法家用抓取场景使用专门绑定的家庭 Agent，不降低控制面 SSRF 保护。每次重定向重新校验，限制响应字节、解压倍率、超时、节点数和递归深度。YAML 安全解析限制别名展开，URI 解码次数有上限。

高级 JavaScript 覆写只在隔离运行时，拒绝网络、文件系统、子进程、动态模块与机密变量。使用 CPU/内存/输出上限和可中断执行；输出节点 AST 重新验 schema。模板存储不能直接成为 HTML；公告、日志、节点名全部作为文本或经过白名单清理，防止持久 XSS。

联邦按妙妙屋consumer经owner转发到Agent的设计实现，consumer操作正文端到端加密，owner保持唯一直接控制者但不能读取正文；可见授权元数据、资源前缀、完整配置授权与密文绑定需按第17份0.3核对。URI、订阅及敏感正文不进转发日志或错误堆栈。

## 可执行验收

1. 跨租户资源 ID、组 ID、导出 ID 不可读取；后端分页与搜索同样授权。
2. CSRF、失效会话、Token 权限不足和过期邀请码均拒绝。
3. 暂停成员不能通过旧订阅缓存恢复权限；客户端旧连接撤销状态独立跟踪。
4. 同一 Agent 命令重放、错误 owner epoch、冲突 hash、过期 artifact 都拒绝或返回原回执。
5. SSRF 通过跳转、IPv6、DNS rebinding、编码 IP 和压缩包绕过的测试应失败。
6. 脚本死循环、巨大对象、原型链污染、文件/网络尝试不影响主服务。
7. TG Mini App initData 重放或过期、伪造付款回调、重复付款事件都不得产生第二份权益。
8. 备份恢复到旧版本时，不能重新激活撤销凭据或重复发放流量预算。
9. Komari 公共响应及历史缓存仅包含获准服务器与字段；关闭公开或撤回字段后不再返回旧数据，前端与日志中无上游凭据。
