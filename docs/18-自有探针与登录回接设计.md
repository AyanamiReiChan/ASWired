# 自有探针与登录回接设计

版本：设计 0.3 / 2026-09-15，尚未实现。最新决策：**除 PRO 商业授权外，采用妙妙屋 X 的设计和公开行为；ASWired 不设置付费墙。** 自有探针、登录回接、JWT、外部第三方仅 Komari 1.2.5-fix2、固定深色及三私有仓继续保留。

## 1. 设计依据与边界

本文件替代0.1/0.2中自定的独立观测进程、专用观测签名协议、BFF会话架构、EdDSA JWT、5分钟访问令牌、7天/30天刷新期限等取舍。公开资料能确认的部分按上游实现；未公开字段、内部握手及持久化细节列为待核对项，不能把此前自拟方案当作妙妙屋内部设计。

| 能力 | 当前采用的设计 | 仓库 |
| --- | --- | --- |
| 自有采集 | Agent 自身的主机观测模块，经节点控制链路上报 | ASWired-Agent |
| 自有监控服务 | 主控保存和提供服务器状态、历史及公开字段，按权限过滤 | ASWired-Server |
| 内置探针 | 主站公开页、标题/Logo/字段、地图/历史、隐蔽登录入口 | ASWired 网站仓 |
| 独立探针 | 静态资源、只读API代理和WS代理部署到同一个Worker，访问密钥保存在Worker Secret | 网站仓提供部署产物，Server提供接口 |
| 登录回接 | 密码/Passkey入口，登录成功后接回主控登录态；用户认证使用JWT | 网站与Server |
| 外部采集来源 | 只读接入Komari 1.2.5-fix2，来源绑定与自有数据分开 | Server |

独立部署自有探针页是展示部署方式，不属于第三方采集供应商。自有采集无需Komari；外部来源的限制不能删除内置或独立探针。Worker部署方式依据[上游外置探针说明](https://miaomiaowux.com/docs/install-external-probe/)。

## 2. 自有探针与数据来源

原生Agent提供CPU、内存、磁盘、网卡/速率、系统信息、在线状态及网络探测，属于Agent本身模块；不强制另设observer进程、专用Ed25519观测身份或自建OBSERVATION_BATCH格式。节点配对、加密通道和上报字段以[子Agent设计](13-子Agent详细设计.md)为准，内部实现未公开的字段须先完成协议核对。

主机/容器观测范围、实际采样时间、缺字段与失联状态需要正确展示；取不到的指标不伪造为0。主机网卡、运行时用户计量与成员账务各自保留来源，不重复计费。原生观测不依赖Komari连接状态；运行时故障及观测故障分别记录。[上游监控能力](https://miaomiaowux.com/docs/features/)

公开探针支持状态HTTP、5秒WS推送目标，以及1h/6h/24h系统和延迟历史窗口；按公开字段说明核对缺值和历史参数。采集器的实际频率、数据库聚合/保留期、断线缓存与补报实现尚不能由页面推送频率推定，不继续固定此前自拟的24小时原始/30天聚合存储方案。[探针接口说明](https://miaomiaowux.com/docs/probe-api/)

Komari是用户指定的外部扩展：按稳定UUID绑定库存，与自有来源分别保存并标注采样时间。管理员明确选择展示来源，不能双计网卡累计或静默拼接两条历史。Komari缺字段、不匹配或断连只影响对应来源；固定版本接口验收见[Komari接入设计](12-Komari探针接入设计.md)。

## 3. 公开接口与部署

公开文档已列出的参考接口如下，开发时按固定版本逐字段建立测试样例；不再采用此前自建的 `/api/public/probe/sites/{siteId}/...` 作为默认目标。

| 上游公开入口 | 对齐内容 |
| --- | --- |
| `GET /api/public/probe-servers` | 允许展示的服务器状态、可选字段与权限 |
| `WS /api/public/probe-ws` | 实时状态与更新频率、断线重连 |
| `GET /api/public/probe-series` | 历史窗口、时间参数、缺值及可见服务器范围 |

路径依据[公开接口文档](https://miaomiaowux.com/docs/probe-api/)。主站与Worker使用同一主控公开投影；保护数据接口时使用独立探针访问密钥。Worker静态资产、只读代理及WS代理一并构建，主控地址需HTTPS；密钥不进入源码或浏览器响应。内置和独立探针可并存，服务器、字段、公开开关及密钥轮换以主控设置为准。

标题、Logo、3D地球、图表、续费时间轴、隐蔽登录入口、屏蔽原登录页、移动端和自定义CSS保留。品牌使用ASWired，外观按用户要求固定深色。公开字段不能因为管理员在同一浏览器登录就变成管理数据；成员资料、管理凭据和代理秘密按权限隔离。具体上游字段可见性按固定样例核对，不另设与其行为冲突的强制展示模式。

## 4. JWT与登录回接

### 4.1 已确定与待核对的部分

用户明确要求JWT。官方[用户管理文档](https://miaomiaowux.com/docs/en/users/#authentication)说明登录后获得JWT，通过 `MM-Authorization` 请求头调用API，令牌过期后重新登录。

同一项目的[公开README](https://github.com/iluobei/miaomiaowuX/blob/main/README.md)另说明 `JWT_SECRET` 存在时使用HMAC签名，未配置时可使用随机token。这里存在公开说明差异：**ASWired按用户要求固定使用签名JWT**，部署必须配置或安全生成签名密钥，不能悄悄切成随机token。HMAC具体算法、claims、header中token是否有前缀、有效期、存储位置和注销机制，需按锁定版本的合法样例/公开实现确认。

| 事项 | 当前约定 |
| --- | --- |
| 用户认证 | 密码/Passkey及上游账户验证流程成功后获得JWT |
| API传输 | 采用公开的 `MM-Authorization` 头；精确值格式按样例核对，不自行改成Cookie-only或Bearer-only架构 |
| 签名与密钥 | 按公开HMAC方向与固定版本确认；用户签名密钥和节点/探针访问凭据分离，不复用上游私钥 |
| 过期 | 按官方公开行为重新登录；撤回自行设定的5分钟JWT、7天空闲/30天绝对期限和强制刷新令牌链 |
| 浏览器存储 | 对齐固定版本真实流程并验证凭据泄漏边界；未确认前不声称上游必用HttpOnly Cookie或localStorage |
| 注销/停用/改密 | 对照上游逐项核对旧JWT后续可用性并实现同样的授权效果；不凭“JWT”推断立即失效或只等自然过期 |

签名、有效期、账户权限与资源范围仍须验证，去除PRO付费授权不会去除用户身份认证。协议细节未核实前不得声称已兼容妙妙屋令牌，更不能接受伪造令牌或从JWT内容指定任意算法/密钥地址。

### 4.2 密码、Passkey与回接

目标流程为：探针登录入口 → 主控验证身份 → 取得/接回JWT登录态 → 返回上游相同语义的管理、成员或探针页面。Passkey及Related Origin Requests、外置探针登录态回接已有公开发布依据。[v0.5.5-beta.1](https://github.com/iluobei/miaomiaowuX/releases/tag/v0.5.5-beta.1)

具体回调路由、跨域传输、临时凭据格式、浏览器来源绑定、Cookie/存储交互、退出后的跨域行为还需核对。此前的BFF强制部署、state+PKCE码交换、专用probe audience及实时session_version查询均不再作为已选定替代架构。实现应基于公开源码或用户合法使用环境的可复现行为，核对来源限制、返回地址和重放处理；资料不足时保留待验证状态，不删减回接功能。

Komari API Key/session_token、独立探针读密钥、Agent token和订阅token属于不同用途，均不能充当用户JWT。登录入口隐藏和原登录页屏蔽不能使正确的密码/Passkey回接失效；相关路径与反代Host行为按上游样例一并验收。

## 5. 核对清单与阶段

| 阶段 | 必做工作 |
| --- | --- |
| P0 | 锁定上游版本；整理探针API、JWT、密码/Passkey及跨域回接样例，解决相互冲突的公开说明 |
| P1 | 同进程原生观测、节点配对上报、用户JWT基础认证 |
| P3 | 内置与Worker独立部署、HTTPS/域名、访问密钥管理 |
| P5 | 全部探针展示/历史与密码/Passkey回接、Komari外部接入 |
| P6 | 逐项比较固定版本行为，完成全部功能与无付费墙验收 |

验收必须覆盖：

1. 无Komari环境下原生采集、内置与独立页、实时及历史可用；指标不冒充宿主或伪造缺值。
2. HTTP/WS/历史的服务器和字段选择、保护密钥、轮换、撤回及失联恢复符合上游公开行为。
3. JWT格式/签名/API头/到期重新登录符合锁定样例；伪造、过期及越权请求拒绝，真实密钥不进入公开数据或日志。
4. 密码/Passkey、关联域、隐蔽入口与屏蔽原登录页组合下回接正确；刷新页面、返回目标、退出/账户停用行为与固定基线一致。
5. Komari仅支持1.2.5-fix2，不影响原生探针或登录；双来源不混算成员账务。
6. 未配置商业许可证、无付费服务器访问条件下，全部自有及原PRO功能可正常使用；身份、节点配对和数据访问权限照常生效。

本轮只修订设计，现有前端仍为合成数据原型。没有部署真实探针或JWT后端，也没有复用或修改上游付费二进制。
