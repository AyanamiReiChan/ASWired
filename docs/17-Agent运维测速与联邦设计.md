## 2. 运行模式与仓库职责

### 2.1 与公开设计一致的进程

| 运行方式 | 结构 | 实际影响 |
| --- | --- | --- |
| embedded | xray-core与管控模块在Agent同一进程 | Agent退出或更新会影响内嵌核心；版本一起发布 |
| external | 独立Xray服务，Agent通过gRPC控制 | 核心可独立升级，Agent与核心分别显示状态 |
| Nginx | 按检测到的系统服务或容器内Nginx管理 | 站点配置、证书与进程状态分别验证 |
| 自有探针 | Agent内部采集与上报模块 | 采集不另装独立observer服务 |
| 家用测速端 | Agent仓独立构建 `cmd/aswired-speedtest` | 运行在测速来源机器，不是节点管理进程拆分 |

Agent内部承担连接、配置、用户/限速/连接跟踪、采集与本机操作。旧稿独立root helper、coordinator、watchdog与内嵌runtime子进程结构不再采用；也不以“进程隔离增强版”替代上游embedded模式。

运行权限随公开安装方式和所需本机管理能力配置。哪些用户与配置操作可以热更新、哪些需要核心或Agent重启，按16的固定模式/核心能力验证，不能把所有操作统一改成整机重启。

## 3. 安装、配置与连接

### 3.1 原生安装

主控添加服务器、选择Xray模式并生成独立token后，提供一键安装命令。安装器检测amd64/arm64，创建配置、安装Agent与所选核心、设置启动方式、启动并检查结果。

| 环境 | 对齐方式 |
| --- | --- |
| systemd | 安装服务定义，启用开机启动，状态与日志入口可用 |
| Alpine/OpenRC | 安装OpenRC服务，使用对应启停和日志路径 |
| 无上述init的LXC等环境 | 按公开脚本采用nohup + rc.local兜底，验证重启后的实际启动 |
| 现有Xray/Nginx | 识别路径、版本、配置与状态，按页面操作安装/复用/接管，不误覆盖其他部署 |

原生默认external，通过相应安装过程准备独立Xray；选择embedded时Agent内置核心，无需再安装一份独立Xray。模式切换前停用受影响节点、保存配置与凭据、切换并验证，显示实际中断范围。

不额外要求用户安装独立特权执行服务、申请节点证书或选择离线账务profile。受限容器按公开支持方式检测；环境确实不能执行所需操作时报告具体原因，不能把不工作的安装写成已支持。

### 3.2 Docker

Docker按官方Agent镜像布局实现：**host网络为默认强制要求，镜像使用embedded模式并预装Nginx**。不再设计bridge端口段profile或允许用户用桥接方案代替默认行为。

主控展示主控地址、服务器token、主控公钥、监听端口和时区等环境配置，并提供配置、Xray配置、Nginx证书和站点配置的持久挂载方式。变量名称在ASWired实现中统一命名，不声称上游二进制能读取改名变量。

启动时验证host网络与模式；错误配置明确失败。动态入站端口使用宿主网络，不要求每新增入站就修改端口映射。容器内Nginx走容器已有程序，安装动作识别其已预装状态。

Docker更新按拉取目标镜像并重建容器完成，保留挂载内容。实际生产发布记录镜像版本与摘要；不向镜像加入PRO许可校验，不增加通用宿主Docker管理接口。

### 3.3 节点配置与身份

| 配置语义 | 处理 |
| --- | --- |
| 主控地址 | 绑定正确主控，连接错误有明确诊断 |
| node/agent token | 每台服务器独立，支持生成、轮换、在线同步和失效处理 |
| master public key | 由主控提供并写入安装配置，用于上游公开说明的加密信道 |
| xray mode | external或embedded，Docker固定embedded |
| connection mode | WebSocket、HTTP、Pull、Auto |
| listen port / 本机站点 | 与服务卡片及实际端口一致，检查冲突 |

主控端记录节点身份、加密状态、连接方式、版本和最后上报时间。token复用冲突应可定位到错误服务器配置，避免两个节点不断互相抢占会话并影响其他节点。

WebSocket为默认主动连接，HTTP为主控直连Agent，Pull为节点取任务，Auto按公开的WS → HTTP → Pull回退顺序工作。网络回退不能关闭token校验或绕过加密要求；Agent管理入口不直接提供给普通浏览器。

### 3.4 加密协议待验证项

采用节点token、主控公钥和上游所述加密信道。旧稿mTLS PKI、节点证书注册、JCS命令签名、SESSION_PERMIT与helper挑战均不再作为默认协议。

P0必须核验：握手方向、主控公钥可信绑定、交换消息、算法与派生、认证失败、重连/轮换、HTTP/Pull等效承载及强制加密行为。当前公开材料没有完整说明时，保留待验证，不捏造securechan字段或宣称私有协议可直接兼容。

实际代码用接口封装连接与加密实现，测试样例与契约在Server仓版本化维护。fakecontrol先覆盖已确认行为；未知协议只能使用明确标注的测试替身，不计入互通通过。

## 4. 在线升级、重装、卸载与配置恢复

### 4.1 用户操作

提供版本提示、单台升级、批量/滚动升级、流式进度和结果；Agent菜单提供更新、重装相关入口及卸载。操作路径跟随公开产品，不要求额外选择双槽、恢复挑战或availability/accounting模式。

发布信息记录Agent、内嵌核心或外置核心的实际版本。升级embedded意味着更新Agent及其内嵌核心；external核心单独更新。更新源和文件完整性核对属于安装实现，不是PRO授权验证。

### 4.2 更新执行

1. 主控确定目标服务器与版本，读取当前运行模式、服务和配置状态。
2. 安装/更新流程保存必要配置和状态，检查架构、可用空间、文件完整性与版本兼容。
3. 按对应安装环境替换程序/镜像、停止并重新启动相关服务；只处理目标部署。
4. Agent重新连接后报告版本、核心与Nginx状态；主控继续检查实际配置和代理连通性。
5. 保留失败日志与可恢复配置，必要时重装已知可用版本或恢复历史配置，结果反映真实状态。

批量发布先在一台验证，再继续其余服务器；进度有每节点结果，可暂停未开始的更新并重试失败目标。取消排队不等于强制回退已完成节点。

不承诺公开资料未给出的原子数据库降级、双槽切换或零中断升级。存在状态格式变化时，发行说明给出已验证恢复路径；未验证降级不能让旧程序直接覆盖新状态或将历史用量归零。

### 4.3 重新安装与卸载

重新执行当前服务器安装命令可停止旧Agent、写入当前配置、覆盖安装并重新启动；保留服务器身份的选择与token轮换状态，避免重装后悄悄生成重复服务器。

卸载区分Agent、独立Xray、Nginx和站点资源，以页面所选对象为准。Agent离线不等于卸载成功；服务停止、文件处理及最终结果必须核对。embedded随Agent退出；external核心是否继续保留按卸载目标和公开操作行为实测，不凭名称猜测。

静态站点内容、上游应用和其他管理方的目录不应误删。保留/清理配置的具体行为进入安装器验收，不能让“卸载Agent”连带清空整个服务器。

### 4.4 配置历史与恢复

记录来自主控操作及Agent上报的配置、hash、时间与来源，提供预览、差异、下发默认配置、恢复历史和节点同步。恢复前先补齐引用证书和所需运行时，验证后生效。

配置恢复不撤销已发生的消费或付款，也不能无意恢复已停用用户。掉线、重复请求和安装中断后以实际核心/文件状态核对，不用一个HTTP成功或在线图标代替资源已生效。

普通掉线与进程重启按Agent/core公开运行方式及16执行，不增加必须在线签发新许可才能启动的产品门槛。具体离线计量、用户截止和回连恢复行为必须实测记录。

## 5. Nginx与站点

### 5.1 支持的操作

| 能力 | 对齐内容 |
| --- | --- |
| 识别与服务控制 | 检测安装路径、版本、运行状态，安装/卸载、启动/停止/重启/重载 |
| 服务环境 | Nginx适配systemd、OpenRC、SysV、直接命令和Docker；与Agent自身init选择分开 |
| 静态站点 | 域名、静态目录、访问配置、证书匹配、创建和删除 |
| HTTP反向代理 | 域名、上游地址、WebSocket与转发头模板 |
| stream | TCP/UDP监听与目标、端口占用、模块能力与实际连通 |
| REALITY本机站点 | Xray/Nginx协同、域名和证书、443占用与Tunnel/回落相关配置 |

公开网站管理说明支持已有Nginx识别与复用，并在删除站点时保留内容。实现应记录哪些配置由本项目创建，避免删除不属于ASWired的站点。[网站管理行为](https://miaomiaowux.com/docs/website-management/)

### 5.2 保存、重载与恢复

站点保存先检查域名、目录、上游、证书和端口；生成配置后使用实际Nginx校验，成功再重载。使用临时文件与替换减少半写配置，失败保留可用配置并显示原因；不新增用户必须操作的prepare/activate协议。

重载后验证实际域名响应、TLS证书、反代/WebSocket或TCP/UDP路径，不能只检查Nginx进程仍在。Nginx自身支持配置重载失败时继续旧配置，但业务是否可用仍需要验证。[Nginx重载说明](https://nginx.org/en/docs/control.html)

扫描现有服务只取得管理所需信息；配置中私钥、密码等内容不进入普通日志。接管既有Xray时先确认管理方，3X-UI和Agent不能同时写同一实例。

### 5.3 REALITY本机站点

保留公开的本机站点向导与部署联动。安装后生成所需Tunnel/回落和Nginx目标配置，检查域名证书及实际访问。模式、端口和协议参数以已验证核心能力生成，不把旧稿自建独立runtime拓扑套入。

主控HTTPS已占用同机443时禁止自动开启冲突的本机站点模式；其他进程占用端口时显示具体冲突，不静默结束对方服务。正常网站访问和代理连接分别验收。

## 6. 证书、DNS与Certimate

主控管理DNS供应商、ACME账户与签发任务，Agent部署证书和更新服务。支持Cloudflare、阿里云、DNSPod、Namesilo，支持DNS-01、根域名/通配符SAN、自动续期、手动PEM上传、下载及删除。

### 6.1 申请与部署

1. 网站配置域名、CA、邮箱、DNS供应商、续期和部署目标。
2. 主控完成DNS挑战、签发与保存，记录证书/私钥、有效期和来源。
3. Agent接收目标证书材料，验证证书和私钥匹配，写入实际Xray/Nginx引用位置。
4. 重载或按核心需要更新配置，返回每目标结果和实际证书指纹。
5. 续期、重新签发或Webhook更新后同步全部引用目标，失败节点保留可重试任务。

DNS/ACME供应方秘密由主控保存，节点只获得部署需要的证书材料。多个挑战并行时只清理本任务创建的记录值；证书申请失败不删除仍有效的旧证书。

证书已保存和已部署是不同状态。离线节点、权限错误、SAN不匹配和服务重载失败须可区分；不能将上传成功显示成全部服务器已更新。

### 6.2 Certimate

保留公开的Webhook上传行为：管理员或具备对应权限的API token调用证书上传接口，接受PEM及公开兼容的旧Base64形式，同域更新并触发部署。[证书与Certimate说明](https://miaomiaowux.com/docs/certificates/)

接口由Server仓实现并加入契约；字段与路径按公开材料核实后固定。不存在PRO校验。不能用主控管理员token为Agent登录，也不把证书私钥放到回执或错误日志。

重复Webhook、旧任务重送和并发续期按证书版本/指纹核对，避免旧证书覆盖当前目标。恢复Xray历史配置时先补齐证书引用，再验证生效。

## 7. 转发、路由、WireGuard、WARP与DDNS

### 7.1 功能归属

| 能力 | 主控与网站 | Agent |
| --- | --- | --- |
| Tunnel/端口转发 | 选择落地节点或自填目标、TCP/UDP、入口地址与端口 | 创建实际监听和转发，检查连通性 |
| 监听复用 | 在已有Tunnel按域名/IP设置目标规则 | 更新关联路由/出站，不重复占用端口 |
| 原生转发链 | 入口/中转/出口组、排序、单入口链、节点或自定义目标 | Agent内转发模块执行本机一跳与状态反馈 |
| 套餐/私有路由子节点 | 父节点可见性、归属、数量/每日次数、凭据和套餐关联 | 建立实际用户路由并执行到期/停用策略 |
| WireGuard | 中转链与地址族、端点和配置页面 | 隧道配置、运行、保活、探活与状态 |
| WARP | 节点独立账号、IPv4/IPv6出站、许可升级与刷新入口 | Agent独立注册、配置/刷新WireGuard出站、卸载 |
| DDNS | DNS凭据、IPv4/IPv6域名、锁定IP、地址替换与同步 | 提供本机地址和入口观测，执行对应节点配置更新 |

已有外部中转地址只改变节点呈现和客户端入口，不应自动再造一条转发。客户端中转组与服务端转发链也分别展示。

### 7.2 交付与资源归属

主控生成拓扑与用户/套餐关联，Agent执行实际配置。端口分配前探测真实占用；换端口后同步入口显示、订阅和相关DNS，不在界面保留错误端口。

多跳链按依赖完成下游配置与入口生效，返回每跳状态；中途失败可重试并清理未引用资源。单入口组链也是有效形态，不强迫用户添加不存在的出口组。

转发改绑、端口切换、套餐变化和节点重启必须保留原用户归属与计费关联。多跳都有观测时不得重复计费；落地不属于某套餐时需要明确归属规则，不能变成无人计费的入口。

子节点用所属用户自己的凭据。删除父节点、成员或转发规则时清理其关联入站/出站/路由，但不能删除其他用户或共享出口。复用监听的目标规则从转发管理入口删除，保持依赖一致。

导入与修改代理配置必须保留必要字段，如VLESS/REALITY flow、传输、安全参数及UDP开关；错误映射不能被泛化成“不属于本面板”。相关回归来自[稳定版变更](https://github.com/iluobei/miaomiaowuX/releases/tag/v0.5.4)和[转发计量修正](https://github.com/iluobei/miaomiaowuX/releases/tag/v0.5.5-beta.5)。

### 7.3 WireGuard与WARP

WireGuard按公开功能保留IPv4/双栈、keepalive、定时探活、失败与延迟。完整参数、实现位置及边界进入固定版本验证；不以自建独立隧道管理服务替代Agent模块。密钥不进入日志，冲突路由或不通路径要能诊断。

WARP采用公开的Agent每节点独立注册与账号、IPv4/IPv6逻辑出站、WARP+密钥升级、刷新配置和卸载行为；不再用旧稿强制的独立Cloudflare官方客户端替换。[公开WARP设计](https://miaomiaowux.com/docs/xray-outbounds/)

注册API、账号材料、WireGuard配置、升级和注销的具体调用若未公开，需要按来源和运行样本验证。刷新应更新已有出站而非重复创建，卸载处理账号注销与关联出站；未知调用结果应核对，不伪造成功。WARP供应方的有效授权由用户提供，不与ASWired的PRO收费挂钩。

### 7.4 地址、DNS与网络检查

支持多个IPv4/IPv6地址、独立IPv6域名、锁定入口IP、DDNS、节点地址同步及恢复原域名。DNS记录更新与实际节点地址分开核对，保存修改来源和失败原因。

真实连通性检查、速度测试与主机探针是不同功能。观测异常不自动清空系统路由、防火墙或成员用量。自定义目标、域名解析和订阅抓取应进行授权与访问范围检查，不能让普通成员借功能读取管理口或元数据。

## 8. 节点测速与家用测速端

### 8.1 公开功能完整保留

测速采用固定mihomo核心，以指定单节点代理实测下载、真实连接延迟和出口IP；支持单/多线程、批量排队、历史和排序。任务离开页面后仍可回看，工作台保留进度与来源选择。

来源包括主控本机和家用测速端。家用端支持Linux、Windows、macOS，反向WebSocket连接主控，不要求家庭公网IP。独立发布入口为Agent仓的 `cmd/aswired-speedtest`，不创建第四仓。

按公开页面保留每来源串行执行节点任务、单任务单流/8路多流和约8秒下载窗口等行为，具体目标和延迟采样算法随固定基线验证。[测速工作台设计](https://miaomiaowux.com/docs/node-speedtest/)

公开材料确认下载与真实延迟；本轮不把未核实的上传测速加入对齐完成标准。

### 8.2 执行、结果与来源

节点配置完整传给测试引擎，经所选代理访问测试目标；不得在失败时静默直连后填入“节点速度”。结果保存实际来源、节点/配置版本、目标、线程数、字节、耗时、出口IP、测试时间及错误。

家用端离线时按公开交互回落主控来源，并明确更新来源标识；家庭网络结果与机房结果不混为同一测试。批量任务执行前展示来源与预期耗流量，主控按用户权限、并发和资源限制受理。

测试会实际消耗所用节点的流量；成员节点与临时测试身份的计费/撤销按既有套餐规则处理，不给测速创造未授权免费额度。取消、超时、断网和重启后核对结果，避免反复重跑造成无界消耗。

### 8.3 安装、token与更新

主控创建测速端并给出一次性配对token及平台安装命令；安装器下载对应程序、设置公开支持的自启动方式并连接。主控支持查看在线状态、轮换凭据和更新测速端。

已审计beta.6记录测速端轮换保留旧token宽限，具体15分钟行为按[原功能集来源](reference/miaomiao-features.json)及[对应发布说明](https://github.com/iluobei/miaomiaowuX/releases/tag/v0.5.5-beta.6)核对。不得把尚未发到用户机器的安装token不停自动轮换而导致无法配对。

测速端只能执行获准测试与独立授权的订阅源中转抓取，不能作为任意远程shell。外部订阅抓取保留URL/重定向/返回大小与访问范围检查；它不取得节点安装、Nginx或主控管理权限。

## 9. 联邦分享：consumer密文经owner转发

### 9.1 架构与保密边界

```text
consumer主控 ── HTTPS + ECDH端到端加密正文 ──> owner主控
                                                   │
                                        校验分享授权并转发密文
                                                   │
                                                   └── 主控加密信道 ──> Agent
```

owner始终是Agent唯一直接控制者；consumer没有Agent直连凭据。消费方管理操作通过owner联邦入口转发，由端到端加密保护正文，**owner主控不能读取consumer具体操作正文**。[官方分享架构](https://miaomiaowux.com/docs/share-server/)

owner处理公开的分享授权、路由和转发所需元信息，不解密consumer正文，不执行旧稿“先读consumer完整业务意图再统一编译”的流程。Agent处理解密后的操作并返回受保护结果；具体密码学端点和消息形式必须由协议验证确认。

这是主控应用层正文隔离目标，不扩写为能抵抗宿主root改写Agent的保证。测试应证明owner网络/应用日志没有consumer正文和解密材料；未完成互通测试前标为待验证。

### 9.2 分享与权限

| owner功能 | consumer默认能力 | 默认禁止 |
| --- | --- | --- |
| 生成/管理/吊销多个分享token，设置完整配置权限 | 查看获准服务器状态和服务版本，创建自己的入站/节点 | 启停/安装/卸载Xray或Nginx |
| 保留服务器名称、地址、额度等管理权 | 编辑/删除自己的入站，按入站给自己用户创建节点 | 修改owner服务器资料、再次分享、直接连接Agent |
| 显式允许接收方查看/修改完整Xray配置 | 授权后进入对应完整配置范围 | 不能仅因有普通分享token就取得全配置权限 |

接入使用owner地址与分享token，可设置本地显示名及固定入站前缀。归属和前缀用于区分资源；默认权限只允许操作自己创建的对象，不能通过改名夺取其他资源。

保留owner明确授予完整Xray配置查看/修改的选项，不强制专用实例。界面显示该授权扩大到完整配置的影响；它不自动授予服务安装、启停、再分享或Agent直连能力。

ASWired双方均无需PRO许可证。节点身份token、分享token、用户JWT、测速端token互不替代，也不把上游商业许可证导入ASWired当作解锁钥匙。

### 9.3 ECDH与授权待验证清单

P0需要核验，不能在文档中假定已解决：

1. consumer与最终解密端的公钥如何交换、可信绑定和验证，owner代转时如何防止密钥替换。
2. ECDH密钥派生、加密帧、nonce/重放、版本与错误格式，结果回传是否同样保护。
3. 节点/分享身份、路径白名单和授权范围如何与密文正文绑定，Agent如何判断普通入站或完整配置权限。
4. owner哪些授权元信息可见、哪些必须保密；不能为方便owner审核而把正文另传明文。
5. token轮换/吊销、旧会话、在途操作和重试如何处理，避免已经撤销的权限继续执行。
6. 多consumer并发与owner自身配置操作如何排序、检测冲突并返回一致结果。

验证路径为固定公开文档/可用源码、用户有权提供的运行样本、双方主控与节点隔离互通测试。没有证据时保持对应协议项未完成；不换成旧稿mTLS、HPKE或owner明文编译并称为对齐。

### 9.4 单一写入与结果

owner负责唯一Agent直接连接和转发调度；Agent在实际配置执行处协调owner本地操作与不同consumer的修改。consumer操作不直接产生第二个外部配置写入者。

重复请求、断线、资源冲突和部分失败返回可核对的实际结果。主控接受或转发成功不等于入站已生效；consumer页面应展示收到的节点结果，不能猜测成功后自行创建第二份资源。

不在此指定未公开的epoch/签名信封或全量编译机制；排序、幂等和结果匹配按核验后的13/16契约实现。功能目标是并发修改可恢复且不覆盖无权管理的对象。

### 9.5 token吊销与资源保留

分享token只在创建时显示，服务端存摘要并显示创建/状态信息，支持多token与吊销。consumer用新token恢复接入的资源认领与归属行为须单独验证，不能自动认领他人入站。

按公开说明，owner吊销token后consumer失去管理权限，既有入站保留；不因为撤销管理token就自动删除服务器上全部consumer资源。正常退出可先清理自己的资源；已失去权限后由owner处理保留资源。

清理只针对明确选中的入站/关联对象，保留其他consumer、owner和用户仍在使用的资源。吊销管理访问、停止服务和删除资源在结果上分别表达，不用一个“已撤销”掩盖尚在运行的入站。

## 10. 自有探针、独立部署与JWT登录

原生主机采集为Agent内部功能，覆盖CPU、内存、磁盘、网络、系统与运行时间等公开范围；保留容器标识和真实可见范围。观测、代理计量和用户会话是不同数据，不因采集失败清空账本或停用正常用户。

Server保存来源、时间、历史、新鲜度与缺口，按服务器/字段白名单生成公开投影。自有来源和外部Komari 1.2.5-fix2分别绑定、存储和选择，不重复累加，也不因Komari未部署或故障而失去原生探针。

网站提供内置探针与独立域名部署，独立Worker按上游公开部署及第18份设计提供展示/回接。提供历史、服务器分组、卡片/列表、地球/时间轴、品牌与受限CSS等完整界面，保持固定深色。

独立展示使用获准公开读接口与已核对的登录回接机制，不转发任意主控管理路径。节点身份凭据和Komari凭据不进入浏览器或Worker展示配置；只读访问密钥与登录身份分离。

密码/Passkey通过ASWired自身身份服务签发签名JWT，使用MM-Authorization，过期重新登录；独立Worker提供静态资源、只读API与WS代理。用户权限由主控校验，读密钥不能兑换用户JWT。不预设强制BFF、专用probe audience、刷新链或授权码机制。

登录返回、JWT存储/有效期、退出/停用效果及跨域/Passkey配置按第18份的固定版本核对清单确定。此部分使用ASWired自有身份，不复用Komari登录会话，未公开字段不写成已确认协议。

## 11. MCP、TG、覆写与页面

MCP、TG Bot/Mini App、订阅JS覆写、DNS/规则集覆写、CSS、备份与日志均属完整功能范围，不按PRO状态锁定。

MCP/TG调用主控相同业务权限和操作接口；脚本覆写在订阅编译流程运行，不下发为Agent远程shell。CSS由网站作用域管理并保持深色，不能作为节点代码执行入口。

主控/节点日志显示连接、安装、同步和任务过程；敏感token、JWT、证书私钥与consumer密文解密内容不进入普通输出。日志可用性不能通过把全部操作正文交给owner实现。
